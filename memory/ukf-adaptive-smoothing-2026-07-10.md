**2026-07-10: added an Unscented Kalman Filter CGM smoother to Boost (Tim's request; he currently runs Exponential smoothing → this is an A/B upgrade candidate).**

**Provenance:** the UKF is NOT Milos's and NOT in AndroidAPS 4.x. Milos only built the pluggable *smoothing framework* (PR #2268, exponential). The UKF is a third-party tsunami plugin (`piecycle`/MTR93600 — same author as the OpenApsAIMI repo) on branch **`devTsuV35_1`**, file `AdaptiveSmoothingPlugin.kt`, already `app.aaps.*` namespace. So "wait for v4" was moot — ported straight into 3.4.

**What it is:** 2-state UKF, state x=[glucose, glucose-rate mg/dL/min], constant-velocity model (Ġ damped 0.98), adaptive measurement-noise R∈[16,196] (default 36, learned online via 48-sample NIS window), fixed Q=diag[1.0,0.40]. Plus safety layers: rapid-rise zero-lag detector (norm-innov>2.5σ+ → inflate Q_rate ×50), compression-artifact rejection (steep drop + IOB<3 → blind-update hold), kinetic-hypo guards (pred-20min<55 / z<80&vel<-1.5 / vel<-3 → force smoothed down). Outputs `smoothed` + a **rate-derived `trendArrow`** (this cleaner velocity is the point for Boost — it feeds the confirm-timing state machine).

**Port (my deliberate 3.4 adaptations, all documented inline):** non-suspend single-arg `Smoothing.smooth(data)` (no SmoothingContext); IOB (compression guard only) via `dagger.Lazy<IobCobCalculator>` (breaks Dagger construction cycle) with **fail-safe** high-IOB default (compression rejection disabled on any IOB error → never masks a real drop); `learnedR` in-memory + >24h-gap reset (dropped the v4-only `DoubleNonKey` persistence and the coroutine/`observeChanges` sensor-change subscription). UKF math is verbatim.

**BACKTEST (`backtesting/scripts/2026-07-ukf-smoothing/`, real CGM `boost_cgm` tim+cohort A–H, ~356k one-step samples). HONEST, mixed:**
- **WIN vs Exponential (what Tim runs):** one-step-ahead predictive RMSE +30–47% every user (pooled 5.56 vs 8.39 mg/dL); ~3.5× less transition lag (+1.25 vs +4.39 mg/dL tracking offset). If smoothing at all, UKF dominates exponential.
- **Marginal vs raw:** +5.2% vs persistence (8/9 users); **ties** the naive raw-delta linear baseline pooled (5.56 vs 5.58) — but linear blows up on the noisiest user (A 8.61 vs UKF 5.16). UKF's real edge = **bounded downside** (never worst), not average accuracy.
- **NOT a denoiser (honest negative):** stable-window variance +5% vs raw, reversals +8%. It's a responsive tracker + de-smooths near hypo by design. Do NOT sell as noise reduction.
- **Fast-carb fix UNCONFIRMED** (the motivation, [[fastcarb-confirm-crash-2026-07-10]]): on the 3 events the UKF velocity is *cleaner* than the spiky raw delta but does **NOT** clearly lead the fall (tied/−30min/−2h behind raw's noisy −5 crossing). Kinetic-hypo guards DO engage on each crash. So it does not demonstrate improved confirm timing — that's still counterfactual-walled.
- **Verdict:** sensing-only support for shadow/selectable eval. NO dosing/TIR claim. Absolute numbers still owe the **golden-vector Kotlin↔Python parity unit-test** (relative ranking is float-robust; absolutes aren't quotable until parity tested) — OFFERED, Tim deprioritised for shipping. Relates to [[insilico-simulation-tooling-2026-07-10]] fidelity discipline.
