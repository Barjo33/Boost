**Boost Analyser** (`boost_analyser.html` at repo root, shipped `507672132c` 2026-07-02) — third self-contained HTML tool next to `boost_simulator.html` + `boost_tuning_guide.html`. Live at `https://tim2000s.github.io/Boost-in-AAPS_3.4/boost_analyser.html`. **GitHub Pages serves from the `dev` branch root** — tools go live on push to dev (another reason for the experimental→dev lockstep).

**What it does:** user enters NS URL + read token (client-side only, token never leaves the browser; NS CORS allows direct fetch). Reads per-cycle shadow telemetry — `openaps.suggested.units` + `boostV5_*` fields; on V6-ACTIVE builds V1's dose is parsed from the reason text `base would=([\d.]+)U`, with `V6 (suppressed|override skipped)` branches → units==V1. Renders: actual TIR + TING/GMI/CV/lows; V1-vs-V6 U/day + per-cycle delta histogram; night(22–07 local)/day/meal splits; auto-detected meal episodes (rise ≥50 mg/dL in 90 min → card with BG curve, V6 state ribbon, paired dose bars, confirm latency, commit shot); state shares; Phase-3 gate tag frequencies. Prominent banner: decision-level comparison, NOT outcome simulation (backtesting-README discipline).

**Architecture notes:** zero external deps (matches the other tools — dark #0f1117, canvas). The analysis core (parseCycles/pairDoses/glycaemia/detectEpisodes/analyse) is DOM-free between `=== CORE ===` markers — extract + run in Node for testing (validated against real cohort NS data before ship: 58/58 cycles paired on Tim's V6-active data). NS API paging: entries backward on `find[date][$lt]` (ms), devicestatus backward on `find[created_at][$lt]` (ISO), count=1000.

**Likely-avoided lows panel (added same day):** the one place the page goes beyond pure decision-compare into estimation. For each BG nadir ≤95: net V1-vs-V6 dose difference over the prior 3h, absorption-weighted (triangular activity, peak 75min, DIA 300min — `absorbedFrac()`), × median LOGGED per-cycle ISF (`variable_sens`, captured in parseCycles) → projected counterfactual nadir range (50% engine-feedback discount on the low end; projections <40 display "well under 40"). Flags BOTH directions (avoided low / would have made worse / other engine would have avoided). Guards: ≥6 paired cycles + ≥0.4U absorbed difference. Banner states limits: counterfactual engine would have reacted (LGS/zero-temp), carbs unmodelled → "pressure toward hypo", not prediction. Validated: real data → 0 events (no nadir ≤95 existed); synthetic 78-nadir → correct SEVERE flag.

**Counterfactual highs + Levers panels (added same day):** peaks ≥180 get the same absorbed-Δdose×ISF treatment — "V6 likely reduced this high" / "V1 would likely have peaked lower — V6 traded peak height for descent safety" (cross-links the lows panel so the trade reads as one story; validated live on Tim's dinner: peak 214 → V1 proj ~108–161). **Lever hints** = rule engine → actual Boost settings: slow-confirm-on-sharp≥200 → fast-carb confirm; commit-shots clipped at logged confirmedCap → confirmed cap; COMMITTED pinned at committedCap while >180 → committed cap; V6-pressure lows (sign flips with mode: active ⇒ extra<0, shadow ⇒ extra>0) → Aggression↓/HypoCaution↑; maxIOB gate binding >200 → review Max IOB; high nights while night-gate holds V6 back → night window/basal not aggression; big peaks with nothing binding → profile not Boost. Not-medical-advice banner + one-lever-at-a-time + Tuning Guide links. parseCycles also captures ccap/fcap/isf per cycle.

**CRITICAL calibration lesson (2026-07-02 night, Tim's challenge):** Tim: "running V1 my TIR was a lot lower (2x TBR)" vs the page's 19.5% projected-V1 below-70. **Empirical anchor from the dual-era DB** (tim, cgm at cycle times): real V1 era (pre 06-11, 52.8k cycles) below70=5.4% TIR=85.3 mean=125; real V6 era 3.7%/84.5/125 — so V6's true win = lows ~1.5×↓ at same mean/TIR, and the naive counterfactual overstated tails ~4×. Root cause: **summing logged per-cycle intents compounds** — each intent was computed against the ACTUAL delivered IOB. Fixes: (1) **IOB-feedback ledger** (counterfactual intent = max(0, other − outstanding unabsorbed counterfactual insulin); symmetric so V1 catches up post-commit) — ONE shared `counterfactualDeltas()` now feeds the daily series AND event windows (thresholds 0.25); (2) zero-temp basal credit **tried and REVERTED — it oscillates** (5h absorption tail + threshold gate rings: below54 rose, TIR crashed, events flipped sign); (3) presentation de-quantified: projected TBR/TIR chips → "low-side pressure window h/day" + "runs-lower h/day"; banner states the validated ~3× overstatement. **Rule: continuous glucose counterfactuals from decision data cannot be quantitative — even bounded models overstate tails ~3×; present as pressure/where, never as %TBR. Event-window projections (3h, single nadir/peak) are the defensible unit.** Feedback-model event magnitudes are physical (dinner 214 → V1 ~166–190; was ~108).

**Ops gotcha:** GitHub Pages branch-deploys can fail with "Multiple artifacts named github-pages" after rapid successive pushes to dev → tool 404s/stale. Fix: `gh api -X POST repos/tim2000s/Boost-in-AAPS_3.4/pages/builds` to force a clean rebuild.

**Rework after Tim's feedback (same evening):** (1) **mode detection is PER-CYCLE** — `boostV5_active` is a recent field, so a global majority-vote misread long lookbacks as V1-shadow and INVERTED every counterfactual direction (Tim caught it); detection = flag OR reason markers (`V6-ACTIVE drove|V6 suppressed (|V6 override skipped`), all maths per-cycle, verdicts name engines from the window's dominant mode, mode line shows V6 ACTIVE/shadow/MIXED(x%). (2) per-episode canvases → **one meal AGP** (episodes aligned at onset: BG median+IQR, median dose per 5-min slot per engine, modal-state ribbon) + compact table. (3) **daily counterfactual AGP**: actual BG time-of-day median+band with projected other-engine median dashed, ≥10 mg/dL divergences shaded (cyan=other lower, amber=higher). 7-day real-data validation: activeShare 0.87→V6 ACTIVE ✓; Tim's week = 6 "V6 likely avoided a SEVERE low" events vs 7 "V1 would have peaked lower" + 1 "V6 reduced this high (270 vs V1 ~317–364)" — the V6 trade (cooler back-end, some peak height) is visible in his own data; lunch + midnight are the divergence zones.

**Limits:** needs shadow-telemetry builds (≥ ~May 2026) — older builds → "update Boost" message; night split uses the VIEWER'S browser timezone; episode detection is heuristic (can merge adjacent rises); unpaired cycles (active build without base-would in reason) are excluded from dose deltas.
