**Oppo Watch X3 / ColorOS WFF runtime: `<Condition>`/`<Compare>` blocks are evaluated only at face LOAD, not per-frame.** `<Transform>` and inline `[COMPLICATION.TEXT]`/`[COMPLICATION.RANGED_VALUE_VALUE]` expressions DO re-evaluate every frame.

**Symptom (2026-06-28):** BoostWFFVariants **bgring** ("Boost BG Ring") face — BG number + ring FILL tracked live, but the band COLOUR stuck on whatever it was at load (e.g. red after a high) until you switched to another face and back (which forces a reload). The colour was chosen by `<Condition><Compare expression=...>`; the fill by `<Transform target="endAngle">` (hence fill updated, colour didn't). This was NOT the 06-27 magnitude/normalisation bug (that fix is correct) — it's a separate runtime-refresh bug.

**Fix:** drive colour with LIVE transforms instead of `<Condition>`. bgring now stacks 5 band layers (ring arcs + number texts) low→high, each shown via `<Transform target="alpha" value="(norm >= threshold) ? 255 : 0"/>`; the highest band whose lower threshold the BG passes is painted on top = correct, live colour. Uses only proven-live primitives (Transform, `>`/`>=`, `?:` — NO `<Condition>`, NO `&&`, NO colour-int literals). norm = `value>1.5 ? (value-40)/310 : value` (see [[boost-v6-experimental-state-2026-06-27]]). Thresholds (fractions of 40..350): 250=0.6774, 180=0.4516, 70=0.0968, 54=0.0452. Built OK (`:watchface:assembleBgringDebug`); APK `watchface/build/outputs/apk/bgring/debug/watchface-bgring-debug.apk`. NOT yet installed/verified on-watch (adb to the Oppo is flaky — wireless-debugging connect refuses/drops; needs re-pair, keep watch screen awake).

**FIXED + VERIFIED (2026-06-28):** colour driven by LIVE `<Transform target="alpha">` per-band stacked layers (highest band whose lower threshold the value passes is drawn on top). **CRITICAL placement gotcha (cost one broken install):** the `alpha` attribute belongs to the `<PartDraw>`/`<PartText>` element, so the `<Transform target="alpha">` MUST be a direct child of the Part — NOT inside the `<Arc>`/`<Text>`. First attempt put it inside Arc/Text → ignored → all layers opaque → last-drawn (very-high red) always won → face went solid RED at every BG. Moving the Transform to Part level (and setting each layer's base `alpha="0"`, base band `alpha="255"`) fixed it; **bgring confirmed correct on-watch by Tim.** (Contrast: `<Transform target="endAngle">` correctly lives inside `<Arc>` because endAngle is an Arc attribute — that's why the ring FILL was always live.)

Applied to all three: bgring (ring+number), tir (number; TIR donut is data-driven WeightedStroke, already live), hrring (HR ring via [HEART_RATE] zones >0/>100/>140 + BG number; hrring also got the raw-mg/dl→magnitude threshold fix it was missing). All build clean (`:watchface:assemble{Bgring,Tir,Hrring}Debug`) and INSTALLED on the Oppo (OWWE261) 2026-06-28. **Committed to BoostWFFVariants `main` as `042552e` (NOT pushed; prior fix ee3b36d was pushed to tim2000s/BoostWFFVariants).** Live-recolour-on-BG-change (without switching faces) follows from the same per-frame Transform mechanism but wasn't yet observed across a real high→normal swing at session end. adb to the Oppo: flaky — `adb connect` to the mdns `_adb-tls-connect` endpoint refuses repeatedly then succeeds; keep retrying + keep watch screen awake; port rotates.
